# No hook events baked into an image

On 2026-10-27, fresh threads on two nodes received the same `session.turn-started` and `session.ended` for Claude session `2c7eb86f-bf2e-4416-b70f-28600c27c4fa`, stamped before either thread existed. These captures come from pylon-th-676f5e5717a4 on infra-testbench, which booted at 09:22:28 UTC from image img-028776ba0456. That image was built from main 1c26e30, the same image those threads booted from.

Where the events came from:

- `disk-scan.txt`. `scan-disk.py` read the pylon's raw disk and found both events as outbox files: a turn start at 08:27:41.334 and a session end at 08:27:42.158, 55 minutes before this pylon booted. The outbox in the home is empty now. The sender that `rootfs-init-extra.sh` starts on every boot delivered them and deleted the files, so only their blocks remain on the disk.
- `build-home.txt`. The home also carries that session's transcript, `~/.claude/projects/-/2c7eb86f-….jsonl`, and a pi session started at 08:27:28 from `/`. Both have whole-second mtimes, as every file copied from the image does. The transcript's prompt is `hi` plus shepherdr's hook context, its entrypoint is `sdk-ts`, and its OS is the build host's Arch kernel, not the pylon's. So the session ran during `docker build`. It is the agent-setup step's check `pi --offline -p hi` (`images/pylon/agent-setup/install.ts`). pi's default provider, `claude-delegation` from `@ramtinj95/pi-claude-delegation`, runs it as a Claude Agent SDK session. That step had already merged the nexus hooks into `~/.claude/settings.json` at 08:27:26, so the session's UserPromptSubmit and SessionEnd hooks wrote to `~/.nexus/outbox`. The hook's only gate was a Claude under the user's own HOME, which the build is. The sender could not reach `nexus.pylon` from the build, and Docker ended it with the `RUN` step, so the image kept the outbox. Every pylon booted from the image starts a sender at boot, and the sender delivers any event less than a day old. So every thread created within a day of the build got the build's session start and end. A template disk is an overlay on the image, so a template built from such an image carried the outbox too.

The fix, run for real in this pylon:

- `run.sh` runs the agent-setup step, `node install.ts`, as a scratch Linux user with `NEXUS_API` on a closed port, then lists what `session-state.sh` finds in that home. On main (`build-state-main.txt`), it leaves the incident's exact shape: a turn start and a session end in `~/.nexus/outbox`, the Claude and pi sessions, notes-compaction state, and a sender still retrying. On this branch (`build-state-branch.txt`), it prints `ok` and leaves nothing. pi's load check now runs only in the smoke boot, whose disk is in memory and thrown away.
- `hook-gate.txt`. A SessionEnd run through the image's current hook in a home without `~/.nexus/pylon.json` queues an event. This branch's hook queues nothing there, and queues the event once the overlay's `pylon.json` exists.

What a captured disk could not show here: no image or template was built. Whether a new image's smoke boot passes the `no build sessions` check, and whether threads booted from it get no stale events, needs an image build.
