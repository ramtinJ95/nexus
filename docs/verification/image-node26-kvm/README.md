# Node 26 and nested KVM in the pylon image

Checked on 2026-10-28 in pylon-th-90d7fb70b62f on `infra-testbench`, which runs the image this change replaces: Node 24.22.1, no `kmod`, no Docker, and no route to nodejs.org or Debian's mirrors. The image itself could not be built here, so `node --version` in the built image, kmod's own `modprobe` and `insmod`, and the smoke boot's new checks wait for the operator's `nexus image build`.

- `nexus-kvm-intel.txt` is what `run.sh` printed. It runs the image's `nexus-kvm` as root, as the pylon-vm controller does, with `shim/modprobe` and `shim/insmod` in place of kmod's. The modprobe shim answers only `--show-depends`, from `modules.dep`, and the insmod shim inserts the decompressed file it is given with `insmod.py`, the `finit_module` call `docs/verification/review-flow/nested-kvm.txt` used on `rj-firebat`. So the step's own decompression and its skipping of loaded modules ran for real. `kvm_intel`, `kvm`, `irqbypass` and `overlay` loaded, `/dev/kvm` appeared with mode 0666, a second run changed nothing, and `kvm-probe.py` as `user` ran a real-mode guest on it. With an insmod that loads nothing, and with one that fails as kmod's does on a host without nested VMX, the step exited 1 and printed the reason. So `infra-testbench`'s Intel host passes nested VMX through, with `nested`, `ept` and `unrestricted_guest` on in `kvm_intel`.
- The step decompresses each module itself because kmod 30's Debian packaging configures xz, zstd and OpenSSL but not zlib, as deepin's copy of it (`deepin-community/kmod`, `debian/rules`) shows, while the Alpine kernel's modules are `.ko.gz`, so `modprobe` could resolve them but not load them. The review of this change caught that, and the first version of the step, which called `modprobe -a`, would have failed on every node. The smoke boot now runs the step itself as its last check, so the build proves the load on the build node.
- `kvm-probe.py` is the probe from `docs/verification/review-flow/` with one change. That probe zeroes the code segment's attributes, which SVM accepts and VMX refuses with `KVM_EXIT_FAIL_ENTRY` (exit reason 9), so on `infra-testbench` it fails before the guest runs. This one sets only the segment's base and selector and keeps the attributes KVM reset it with.

Node 26.12.1's official linux-x64 binary links `libatomic.so.1`, which bookworm-slim lacks, as the official `node:26-bookworm-slim` image's own `apt-get install libatomic1` shows. The binary from the npm registry's `node-linux-x64@26.12.1` failed here with `libatomic.so.1: cannot open shared object file` until a stand-in library was installed in this pylon. With it, the typecheck and the full suite passed on Node 26.12.1, on main and on this branch.

The pin's checksum is the `node-v26.12.1-linux-x64.tar.xz` line of the signed SHASUMS256 in nodejs.org's own release post, `apps/site/pages/en/blog/release/v26.12.1.md` in `nodejs/nodejs.org`. The same file for 24.22.1 holds the checksum the recipe pinned before, and `nodenv/node-build` lists the same `.tar.gz` checksum for 26.12.1.
